# 对象存储防误删：版本控制、软删除、回收站与保留策略

对象被同名覆盖、被删掉，或者整个桶被清空之后，还能不能找回，取决于删除当时桶上开了哪一层保护。版本控制、删除标记、软删除、回收站、保留策略、对象锁定和不可变性（WORM），挡住的不是同一种操作。有的只让「普通删除」变成标记，指定版本 ID 仍然会永久删掉；有的在保留期内连拥有者都删不掉，但普通删除仍可能盖上一层删除标记，列表里看起来像已经没了。

这篇只写对象被覆盖、被删除或桶被清空之后的找回边界：各云已打开页面写明的版本控制、删除标记、软删除、回收站、保留策略 / 对象锁定 / 不可变性分别挡住哪一层，开启之后从哪里恢复，以及哪些操作仍然会永久删除。私有桶、预签名 URL 和谁能凭链接读到对象，见 [对象存储私有桶与临时访问链接](object-storage-private-bucket-presigned-url.md)。存储类型、生命周期转换或过期、最短存储时长和提前删除费，见 [对象存储存储类型与生命周期](object-storage-storage-class-lifecycle.md)。那篇只把版本控制、软删除和 WORM 当作「生命周期删除会落到哪一层」来提及；历史版本怎么清理，下面写机制，单价和最短时长表不抄到这里。谁有权改版本控制、删指定版本、关保护，见 [云账号登录和权限怎么收紧](cloud-account-mfa-least-privilege.md)。对象存储不是云盘快照。磁盘在某一时刻的副本、回滚和自定义镜像，见 [云盘快照与自定义镜像](disk-snapshot-custom-image.md)。那些内容这里不重复。

## 先看这几件事

1. 先确认误操作发生时，桶有没有版本控制或软删除。阿里云版本控制概述的对照表写明：未开启时，覆盖后已有对象无法恢复，删除后无法再获取该对象。腾讯云版本控制概述把未启用写成默认初始状态，上传、查询和删除方式不变，没有另写一句「删了还能从回收站捞回」。AWS 版本控制页写默认关闭，必须显式开启。Azure 的软删除与版本控制对照页写这两项默认都禁用。Google Cloud 的版本控制参考表写：版本控制和软删除都关闭时，删除或替换实时对象会永久删除旧内容。
2. 开启版本控制之后，不带版本号的删除，多数页面写成留下历史版本，而不是立刻把字节擦掉。阿里云、腾讯云和 AWS 已打开的页面把这种删除写成插入删除标记，当前版本变成这个标记，不带版本号的 GET 会表现为对象不存在。Azure 版本控制页不使用「删除标记」这个词：不指定版本 ID 的删除，是把当前版本变成先前版本，并且不再有当前版本。Google Cloud 在只开启版本控制、不指定 generation 时，实时版本变成非当前版本，generation 不变。指定版本 ID、版本号或 generation 的删除，是另一条路，见下面各章，不要和普通删除当成同一步。
3. 版本控制开了之后，阿里云、腾讯云和 AWS 已打开的页面都写不能回到「未开启」，只能暂停。暂停不是把已有历史版本清掉。Azure 和 Google Cloud 已打开的页面写可以禁用或关闭版本控制；关掉之后不再产生新版本，已经存在的版本还在，直到你再删。桶上如果还有对象锁定、保留策略或对象复制，能不能暂停或关闭，以各章原文为准，不要假设总能暂停。
4. 「回收站」和「软删除」不是各云都有、也不是默认都开。阿里云版本控制概述写「当前 OSS 不提供回收站功能」。腾讯云中国站有单独的回收站控制台页，依赖版本控制，开启回收站会同步开启版本控制；国际站对应编号这次是 404。AWS 这次打开的 Recycle Bin 页列出的资源是 EBS 卷、EBS 快照和 EBS-backed AMI，名单里没有 S3 对象。Azure Blob 软删除要自己开，保留天数在软删除页写成 1 到 365 天。Google Cloud 软删除页写：支持该功能的桶默认启用，默认保留 7 天。这 7 天只属于今天打开的 Google Cloud 软删除页，不要套到其他云。
5. 保留策略、对象锁定和不可变性挡住的是保留期内的删除和覆盖，通常不挡住「再上传一个新版本」或「再插入一个删除标记」。阿里云桶级保留策略页、AWS Object Lock 页和 Google Cloud 的 Bucket Lock、Object Retention Lock 页都写了：保护期内不能删、不能改受保护的那一版；同名上传仍可能产生新版本，新版本是否继续受保护，各页不一样。删除标记在阿里云和 AWS 已打开的页面里不受保留策略或 WORM 保护。因此列表里看不到当前文件，不表示历史版本已经被永久擦掉，也不表示你已经绕过了保留期。
6. 普通删除可恢复，不自动覆盖这三件事：按版本 ID 永久删除、生命周期到期删历史版本或非当前版本、删除整个桶或容器。阿里云和 AWS 已打开的页面写，生命周期作用在当前版本上时是加删除标记，作用在历史版本或非当前版本上时是永久删除且无法恢复。Azure 在启用软删除时，生命周期删除会进入软删除。Google Cloud 在启用软删除时，被生命周期删除的对象会变成软删除；若同时开了版本控制，删实时对象会先变成非当前版本，删非当前版本才变成软删除。删桶能不能靠这些功能找回来，见对照表，这次没读到的不补。
7. 历史版本、删除标记和软删除对象会不会继续占容量，只按各页写的机制理解。阿里云写版本控制功能本身不收费，当前版本和全部历史版本都收存储费。腾讯云中国站回收站页写历史版本仍产生存储容量费用，删除标记不计费。AWS 写每个版本都是完整对象，不是与上一版的差值，按每个存着的版本计。Azure 写软删除数据在永久删除前按与活动数据相同的费率计。Google Cloud 写非当前版本按它仍为实时版本时的同一费率计，软删除对象在保留期内继续产生存储费。单价、最短存储时长和提前删除费见生命周期一文，这里不抄表。清理规则执行之后，容量不会在点击保存的同一秒变成零。

## 阿里云

中国站规则来自 help.aliyun.com。国际站英文页与中国站一致的部分会注明 Last Updated；只在一边读到的，不抄到另一边。菜单名按各页原文保留。

### 未开启时，覆盖和删除按概述表是找不回

[开启版本控制](https://help.aliyun.com/zh/oss/user-guide/overview-78/)（页上未见更新日期）把版本控制写成 Bucket 级保护。默认状态是「未开启」。数据保护表写明：

- 未开启：覆盖时已有 Object 被直接覆盖且无法恢复，只能拿到最新版本；删除是直接删除，无法再获取此 Object。
- 开启：覆盖生成新版本，历史版本不受影响；删除把 Object 标为已删除，历史版本不受影响，可恢复。
- 暂停：覆盖仍生成新版本，若已有暂停期的同名版本则覆盖它，其他历史版本不受影响；删除同样打上已删除标记，若已有暂停期的删除标记则覆盖它。

使用场景里写：当前 OSS 不提供回收站功能。误删后想找回，用的是版本控制，而不是一个名为回收站的功能。这次检索后实际打开的是版本控制、生命周期管理版本、桶级保留策略、对象级保留策略，以及国际站对应页，没有另开到一份标题就是 OSS 回收站、并把误删对象放进可恢复列表的现行产品页。不要把这句扩成「阿里云其他产品也都没有回收站」。

版本控制功能本身不收取任何费用。当前版本和所有历史版本都收取存储费用。下载或恢复历史版本还会产生请求费用和流量费用。计费项和单价见生命周期一文所指向的计费说明，这里不抄。要彻底停止 OSS 费用，该页写的是删掉 Bucket 内全部数据，包括 Object、碎片和历史版本，再删 Bucket 本身。这是停费路径，不是「删了还能从回收站恢复」。

只有 Bucket 拥有者以及被授予 `PutBucketVersioning` 的 RAM 用户能配置版本控制。谁应当拿到这个权限，见最小权限一文。

版本控制处于开启或暂停时，禁止覆盖规则不生效，上传时的 `x-oss-forbid-overwrite` 也不生效。同一 Bucket 不能同时开 OSS-HDFS 和版本控制。国际站 [Enable versioning](https://www.alibabacloud.com/help/en/oss/user-guide/overview-78/)（Last Updated: Sep 09, 2026）的默认状态、三行对照表、「OSS does not have a recycle bin」、费用只说功能本身免费而各版本仍计存储费，以及禁止覆盖头和 OSS-HDFS 互斥，与中国站同方向。

### 开启之后只能暂停，恢复不要选删除标记

开启后不能回到未开启，可以暂停。控制台：新建 Bucket 时，版本控制开关默认未开通；已有 Bucket 走「数据安全 > 版本控制」，单击立即开启。暂停也在同一页。暂停后，新上传对象的 versionId 为 `null`，已有历史版本继续保留。国际站同一路径的英文是 Content Security > Versioning，开关默认 Off。

[开启版本控制下 Object 的操作](https://help.aliyun.com/zh/oss/user-guide/manage-objects-in-a-versioning-enabled-bucket)（页上未见更新日期）：

- 不指定版本 ID：Object 被标为已删除，当前版本和历史版本默认都不删，之后可以恢复。
- 指定版本 ID：永久删除该版本。
- 生命周期的 Expiration 作用于当前版本，把当前版本转为历史版本保留，不是把当前版本字节擦掉。
- NoncurrentVersionExpiration 作用于非当前版本，永久删除这些版本，且无法恢复。

控制台要看历史版本：文件管理 > 文件列表，单击历史版本右侧的「显示」。彻底删除历史版本之后无法恢复。该页建议用复制的方式恢复，而不是先永久删掉当前版本：指定版本 ID 永久删除当前版本后，下一个历史版本会变成当前版本，但被删的那一版找不回。

控制台恢复：同一个 Object 仅允许恢复其中的某个历史版本，且该历史版本不能为删除标记。可以恢复单个，也可以选中多个 Object 的目标历史版本后点页面下方的恢复。国际站 [Manage objects in a versioning-enabled bucket](https://www.alibabacloud.com/help/en/oss/user-guide/manage-objects-in-a-versioning-enabled-bucket)（Last Updated: Oct 08, 2026）的删除和生命周期两句与中国站同方向，恢复入口是 Object Management > Objects，Show next to Previous Versions。重要说明的英文是一次只能恢复一个对象版本，删除标记不能被恢复；同一页紧接着又写了 Restore multiple objects。这两句都留在英文页上，不要改写成和中国站「同一个 Object 只恢复其中一个历史版本」完全同一句。

通过生命周期清理历史版本的示例天数，生命周期管理版本页用了 90 天。那是该页例子，不是必须值。规则怎么和存储类型、最短时长叠在一起，见生命周期一文。

### 桶级保留策略：锁定前有 24 小时，锁定后不能缩短

[Bucket 级别保留策略](https://help.aliyun.com/zh/oss/user-guide/oss-retention-policies)（页上未见更新日期）是 WORM。保留时间到期前，任何用户包括资源拥有者都不能修改和删除 Bucket 中的 Object，只能上传和读取。到期后才可以修改或删除。

前提写成：版本控制须为开启或未开启，暂停不支持设置保留策略。创建后策略处于 InProgress，有效期 24 小时。24 小时内未锁定，拥有者和授权用户可以删除策略；超过 24 小时仍未锁定，策略自动失效，也可以删除。一旦锁定，不能删除策略，不能缩短保护周期，只能延长。保护期内删除或修改数据返回 `409 FileImmutable`。控制台路径是「数据安全 > 桶级别保留策略」。保留周期以天为单位，取值 1～25,550。这是该页对话框说明里的范围，不是建议你设满。

Bucket 内对象在保留期内，生命周期仍可做存储类型转换；转换费用和最短时长见生命周期一文。BucketWorm 与 ObjectWorm 互斥，同一个 Bucket 不能同时开。同一 Bucket 也不能同时开 OSS-HDFS 和桶级保留策略。

保留时间按对象最后修改时间加保留周期算。该页例子：保留 10 天、最后修改时间为 2022-02-15，则保留到 2022-02-25。这是例子，不是默认 10 天。

删除 Bucket：里面没有 Object 时可以直接删。对象已过保护期时，先删掉全部 Object 再删 Bucket。仍有对象在保护期内时，不能删策略，也不能删 Bucket。该页同时写：欠费时，即使对象还在保留策略保护期内，仍会按欠费停服规则删除数据。停服天数这次没有在这一页读到，不补。

国际站 [Bucket-level retention policy](https://www.alibabacloud.com/help/en/oss/user-guide/oss-retention-policies)（Last Updated: Oct 08, 2026）的 24 小时、锁定后只能延长、`409 FileImmutable`、1 to 25,550 天、欠费仍可能删除，与中国站同方向。控制台英文是 Content Security > Bucket-level Retention Policy。

### 对象级保留策略是邀测，而且开了就不能关

[对象级别保留策略](https://help.aliyun.com/zh/oss/user-guide/object-level-retention-policy-object-worm)（页上未见更新日期）写明目前为邀测，要联系技术支持开通。它依赖版本控制：未开版本控制不能开 ObjectWorm；开了之后版本控制也无法关闭。警告写此操作不可逆，除非注销阿里云账号，否则不能关闭 ObjectWorm。

当前仅支持合规模式（COMPLIANCE）。保留期限内任何用户包括根用户都不能删除或覆盖写受保护的 Object 版本。保留截止日期只能延长，不能缩短。时间是绝对的 RetainUntilDate，精确到秒。BucketWorm 则是相对天数，从最后修改时间算。二者互斥。

默认保留策略只对之后新上传的文件生效，存量文件要单独用 PutObjectRetention 设置。对象自己的策略优先于 Bucket 默认策略。删除标记不受保护，可以创建和清理，但保留期内的对象版本不能删。分片上传产生的 Part 不受保护。生命周期的存储类型转换不受影响，保留期内的文件不会被 Expiration 自动删除。控制台路径是「数据保护 > 对象级别保留策略」，和桶级策略的「数据安全」不是同一个菜单名。

国际站 [Object-level retention policy](https://www.alibabacloud.com/help/en/oss/user-guide/object-level-retention-policy-object-worm)（Last Updated: Sep 21, 2026）同样写邀测、仅合规模式、开启后 ObjectWorm 和版本控制都不能禁用。控制台是 Data Protection > Object-Level Retention Policy。

### 同一站点里，「暂停」能不能配保留策略，两页不一样

不要把下面几段收成一句「官方就是不能」或「官方就是能」。

版本控制概述的「与保留策略协同工作」写：两者可同时配置，开启顺序没有约束。允许的组合是保留策略加版本控制未开启，或保留策略加版本控制开启。版本控制处于暂停的 Bucket 无法开启保留策略。已开启保留策略后，不允许从开启转为暂停，也不允许从未开启转为暂停。保留策略保护所有版本，保护期内不能删除或篡改任何版本；允许同名上传产生新版本，新版本同样受保护。保留策略不作用于删除标记。

同一篇概述的「暂停版本控制」又写：如果 Bucket 已开启保留策略，从「开启」转为「暂停」被禁止，从「暂停」转为「开启」是允许的。

保留策略页的前提仍是：暂停不支持设置保留策略。同页「与版本控制协同工作」却写：版本控制处于暂停的 Bucket 可以开启保留策略，开启后可以改为开启。FAQ 再写三条：锁定保留策略后，开启不能转为暂停；暂停状态在开启保留策略后仍可转为开启；未开启版本控制的 Bucket 配置保留策略后可以开启版本控制。同页还写：同时开启时，删除会产生删除标记，不会实际删除历史版本；生命周期可以清理悬空删除标记，不能删除受保护的对象版本。

国际站版本控制页的协同一节同样写不能在 Suspended 上开启保留策略，保留策略页的协同一节同样写可以。操作前以你这次在自己站点、自己 Bucket 上实际得到的报错为准，不要用这篇把两页合成一个开关顺序。

复制相关也有两句，都留着：版本控制概述写目标 Bucket 上的文件在保留周期内删除报错，不在周期内删除成功。保留策略页写源 Bucket 的版本删除不会同步到已开启保留策略的目标 Bucket。

### 版本控制默认关闭，普通删除是删除标记

[版本控制概述](https://cloud.tencent.com/document/product/436/19883)（最近更新时间：2022-04-13 10:21:13）把三种状态写成：未启用（默认）、启用、暂停。一旦启用，不能回到未启用，可以暂停。启用前已在桶里的对象，版本 ID 为 null。启用或暂停改变的是之后请求怎么处理对象，不改对象本身。只有主账号和授权子账号可以暂停版本控制。

启用状态下：

- 不指定版本 ID 的 DELETE，不会删掉该对象，而是插入一个带新版本 ID 的删除标记，标记成为当前版本。对该标记做 GET，COS 认为对象不存在，返回 404。概述把这一步比作放进「回收站」，但没有完全移除对象。
- 指定版本 ID 的删除，永久删除该版本。
- 恢复有两种：把早期版本复制到同一桶，复制结果成为当前版本，所有版本都还在；或者永久删除当前版本，使前一个版本变成当前版本。

暂停状态下，新上传对象的版本 ID 为 null。若已有 null 版本，再次上传会覆盖它。简单 DELETE 时，若存在 null 版本，会插入删除标记替换它；删除标记没有内容，null 版本原来的内容会丢失。若没有 null 版本，简单 DELETE 只插入删除标记，不删除已有内容。即使已暂停，主账号或被主账号授权的账号仍可以永久删除指定版本。

[数据防误删和误删恢复实践](https://cloud.tencent.com/document/product/436/106495)（最近更新时间：2026-05-14 16:35:32）的控制台路径是：容错容灾管理 > 版本控制，编辑开启状态。开启后在文件列表单击「列出历史版本」。恢复被误删对象的 API 说明是：删除请求生成删除标记作为最新版本；删掉最上层删除标记时，调用 DeleteObject 必须带删除标记自己的 versionId，原先的历史版本才会成为最新版本。另一条是 PutObject-Copy，在复制源里写明要恢复的历史版本号，从而产生一个新的最新版本。

### 中国站回收站是单独功能，开它会连带开版本控制

[设置回收站](https://cloud.tencent.com/document/product/436/112126)（最近更新时间：2026-08-07 17:26:03）写：回收站给被误删的数据一个临时存放处。开启后，被删除的文件不会被永久删除，而是进入回收站。回收站列表会列出所有文件的历史版本和删除标记。

它依赖版本控制。开启回收站会同步开启版本控制。控制台：存储桶列表，进入桶，回收站列表，开启回收站，确定。页上没有写成新桶默认已经开着。

还原单个历史版本时，可以选择还原后是否删除原历史版本。也可以批量还原。清空历史版本要输入存储桶名称；清空后历史版本被彻底删除，不可恢复和访问。当对象的最新版本是删除标记时，该页写执行删除操作会把对象还原为上一个历史版本。这和「清空」不是同一步。

历史版本定期清理会自动配一条生命周期规则，按你填的天数删除历史版本和无历史版本的删除标记。若桶上已经有历史版本删除规则，开启后按规则执行优先级执行。关掉这个开关，会同步删掉这条生命周期规则。天数怎么和存储类型最短时长叠在一起，见生命周期一文，这里不把该页的开关写成必须设成某一天。

容量：回收站内文件仍产生存储容量费用，删除标记不计费。低频、归档和深度归档的最短存储时长，该页写分别是 30 天、90 天、180 天，提前删除按对应类型的最短时长计。这是回收站页指向提前删除说明的原句，不是这篇要重抄的价目表；类型之间的差异和例外以生命周期一文核对过的页面为准。

实践页的恢复入口是进入回收站列表，确认已开启，再批量还原。也写了可以在回收站管理页对多个存储桶开启。访问控制和 MFA 操作保护在实践页是另一层：账号中心安全设置里绑定 MFA 并勾选操作保护后，文件列表里点「清空存储桶」会弹出 MFA 校验。这是账号操作保护，不是 AWS 那种桶上的 MFA Delete。谁应该有清空和删版本的权限，见最小权限一文。

### 对象锁定默认不锁存量，和回收站不是同一个开关

[对象锁定概述](https://cloud.tencent.com/document/product/436/55294)（页上未见更新日期）写：可以设定保留期限内对象不可改写、不可删除。功能当前是对象级别。开启桶的对象锁定，只是把桶标成「可使用对象锁定」，不会自动给桶内所有对象加锁。可以对指定对象锁定，也可以不锁。

对象一旦设置了锁定，不能解除，不能缩短保留期限，只能延长。多 AZ 桶暂不支持。基于该功能，页上提到可满足 SEC Rule 17a-4(f)、FINRA 4511、CFTC 1.31 等要求，并转述了法规对记录保留的要求。那是法规背景，不是 COS 给你设好的默认保留天数。

限制里和误删直接相关的几条：

- 白名单功能，要联系开通。实践页同样写白名单。
- 版本控制处于暂停的桶，不能开对象锁定。同时开了对象锁定和版本控制的桶，不能暂停版本控制。页上没有写「未启用版本控制的桶能否开启」，这句不补。
- 不支持智能分层。已开智能分层的桶不能开对象锁定，反过来也不行。
- 不支持追加上传。
- 保留期内，生命周期的沉降和删除都不生效。该页例子：20 天沉降对 30 天保留，要到上传后第 31 天才沉降；20 天删除对 30 天保留，第 31 天才删除。保留期更短时，到期后的生命周期按原规则执行。这是例子，不是推荐天数。
- 文件碎片不受对象锁定限制，可以清除。
- 功能开启后不能关闭。
- 开启后，存储桶和对象 ACL 仍可修改。

保留期限存在对象元数据的 RetainUntilDate 里。到期前不能删除、不能修改对象，也不能改存储类型，不能改页上列出的 HTTP 头和 `x-cos-meta-` 用户元数据。上传时若带了 `x-cos-object-lock-retain-until-date`，以头部为准，忽略桶的默认天数。没带头部时，才用桶的默认保留天数；桶没配默认且上传也没带头部，则不锁定。桶的默认保留天数可以缩短、延长或关闭，且只影响之后新增的对象，不影响已经锁上的存量对象。概述写开启桶配置的方法是 API `PUT Bucket ObjectLockConfiguration`。实践页另给了控制台：安全管理 > 对象锁定，编辑并配置保留时间后保存，并指向「设置对象锁定」。设置对象锁定专页这次没有单独打开。控制台点击和 API 限制不要合成「一个开关就把存量全部锁死」。

## AWS

以下来自 docs.aws.amazon.com。没有打开 docs.amazonaws.cn。中国区账号不要把下面的控制台路径当成中国区文档已经核对过。

### 简单删除留下删除标记，带版本 ID 的删除不能撤销

[S3 Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html)（页上未见更新日期）：版本控制默认关闭，必须显式开启。桶只有三种状态：unversioned、versioning-enabled、versioning-suspended。开启后不能回到 unversioned，可以暂停。状态作用于桶内全部对象，不能只对一部分对象开启。开启前已存在的对象版本 ID 为 `null`，开启本身不改变这些对象；之后的修改才会给出版本 ID。

已开启时，删除对象会插入删除标记，而不是永久移除；标记成为当前版本。覆盖会产生新版本，先前版本可以恢复。每个版本都是完整对象，不是与上一版的差值。三个版本就按三个对象计存储和传输。单价见生命周期一文，这里不抄。

若未开启版本控制时已经有过期删除的生命周期，开启版本控制后还想要同样的「永久删除」效果，必须再加一条非当前版本过期配置。否则当前版本的过期不会把对象永久删掉。

[Deleting object versions](https://docs.aws.amazon.com/AmazonS3/latest/userguide/DeletingObjectVersions.html)（页上未见更新日期）把两种删除分开：

- 版本控制开启时，不带版本 ID 的简单 DELETE 不能永久删除对象，只插入删除标记。对当前版本已是删除标记的对象做 GET，返回 404，对象并未被擦掉。
- 永久删除必须使用带 `versionId` 的 DELETE。控制台在对象的 Versions 里勾选版本，删除时输入 `permanently delete`。该页警告：永久删除对象版本之后不能撤销。
- 生命周期的 Expiration 作用于当前版本：不删除当前版本，而是加删除标记，标记成为当前版本。NoncurrentVersionExpiration 永久移除非当前版本，永久移除的对象不能恢复。

非当前版本只要还在，就继续按正常费率计存储和传输。

[Managing delete markers](https://docs.aws.amazon.com/AmazonS3/latest/userguide/ManagingDelMarkers.html)（页上未见更新日期）：在已开启版本控制的桶里删除对象后，各版本都还在，S3 会创建删除标记。要取消这次删除，必须再删掉这个删除标记，而且请求里要带删除标记自己的版本 ID。去掉之后，简单 GET 会取到下一个版本。如果当前版本已经是删除标记，再不带版本 ID 发一次 DELETE，不会去掉它，而是再放入一个新的删除标记。版本 ID 为 `NULL` 的删除标记，也要把 `NULL` 作为版本 ID 传进去。控制台：打开 List versions，勾选要恢复的对象旁边的删除标记，删除时输入 `permanently delete`。该页写不能用控制台取消删除文件夹，文件夹要改用 CLI 或 SDK。生命周期可以清掉「过期删除标记」：所有对象版本都已删除、只剩一个删除标记时，若配置会删除当前版本，或显式设置了 `ExpiredObjectDeleteMarker`，S3 会移除这个删除标记。这是永久去掉标记，不是把数据再留一层。

### MFA Delete 只保护改版本状态和永久删版本

[Configuring MFA delete](https://docs.aws.amazon.com/AmazonS3/latest/userguide/MultiFactorAuthenticationDelete.html)（页上未见更新日期）：可以在版本控制之上再要求 MFA。需要额外认证的操作是两类：改变桶的版本控制状态，以及永久删除一个对象版本。认证是安全凭证，加上设备序列号、一个空格、设备上的六位码。启用或关闭 MFA Delete 用的是配置版本控制的同一套 API，状态存在 versioning 子资源里。

桶拥有者、创建桶的根账号以及所有被授权用户可以开启版本控制。只有桶拥有者（根账号）可以开启 MFA Delete。不能在 AWS 管理控制台里开启，要用 CLI 或 API。该页写不能把 MFA Delete 和生命周期配置一起用。在已开启 MFA Delete 的桶里删除对象，控制台不可用。带 `x-amz-mfa` 的请求必须走 HTTPS。

这是桶上的删除保护，和登录控制台的 MFA 不是同一个开关。登录和最小权限见另一篇，这里不重复怎么绑设备。

### Object Lock 开了就不能关，也挡不住删除标记

[Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html)（页上未见更新日期）用 WORM 防止对象在一段固定或可变时间里，或无限期地被删除或覆盖。只在已开启版本控制的桶里工作。锁信息存在被锁的那一个版本的元数据里。保留期和法律保全只保护请求指定的版本，不阻止创建新版本，也不阻止在上面再加删除标记。同名上传会得到新版本，旧的受保护版本继续按它自己的保留配置锁着。

两种保留模式：

- Compliance：任何用户包括账号根用户都不能覆盖或删除该版本。保留模式不能改，保留期不能缩短。到期之前要删掉该版本，该页写的唯一办法是删除关联的 AWS 账号。
- Governance：没有特别权限的用户不能覆盖、删除或改锁。要绕过，必须同时有 `s3:BypassGovernanceRetention`，并在请求里显式带 `x-amz-bypass-governance-retention:true`。控制台在你拥有该权限时会默认带上这个头，因此在控制台删除受治理模式保护的对象会成功。谁不该拥有这个权限，见最小权限一文。

法律保全没有到期日，直到有 `s3:PutObjectLegalHold` 的人去掉。它和保留期互不影响：保留期到了，法律保全还在，对象仍不能删；去掉法律保全时若保留期未到，对象仍受保留期保护。

可变保留（variable retention）在该页是另一套：先打开 event hold 并给出时长，释放 hold 时才把 retain-until-date 定为释放时刻加时长。持有期间，计算出来的日期不会被改成比当前值更早。这和固定填写 retain-until-date 不是同一个字段用法。桶策略可以把保留期限制在一定范围内；该页写最大保留期是 100 年。event hold 时长须为正整数，最长 36,500 天或 100 年。这些是该页写的上限，不是默认值。

删除时的返回码：对象正被保留期或法律保全保护时，带版本 ID 的永久 DELETE 返回 `403 Forbidden`；不带版本 ID 的简单 DELETE 返回 `200 OK`，并插入一个新的删除标记作为当前版本。

[Object Lock considerations](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-managing.html)（页上未见更新日期）写明：一旦在桶上开启 Object Lock，就不能关闭 Object Lock，也不能暂停该桶的版本控制。开启了 Object Lock 的桶不能当作服务器访问日志的目标桶。生命周期仍可对受保护对象工作，包括放置删除标记，但锁定的版本不能被生命周期过期政策删除。换存储类型不会去掉锁。删除标记不受 WORM 保护，无论底层对象有没有保留期或法律保全。Object Lock 不保护加密密钥：用 AWS KMS 加密时，密钥被删掉之后对象可能无法读取。

[Configuring S3 Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-configure.html)（页上未见更新日期）：锁对象之前，必须先在通用桶上开启版本控制并开启 Object Lock。创建桶时，控制台步骤里要自己把 Bucket Versioning 选成 Enabled，再开 Object Lock。已有桶也可以之后再开。开启之后不能关，也不能暂停版本控制。

### Recycle Bin 这次读到的名单里没有 S3 对象

[Recycle Bin](https://docs.aws.amazon.com/ebs/latest/userguide/recycle-bin.html)（页上未见更新日期）写它用于恢复被误删的 EBS 卷、EBS 快照和 EBS-backed AMI。支持的资源类型就是这三类。归档层里的归档快照若匹配保留规则，也会按规则留在 Recycle Bin 里。页上没有把 S3 对象或 S3 桶列进支持名单。因此不要把 EBS 的 Recycle Bin 写成 S3 的回收站。S3 对象这次能对上的找回路径，是版本控制的删除标记、带版本 ID 的永久删除，以及 Object Lock。删除整个通用桶之后版本还在不在，这次没有打开删桶专页，不补。

## Microsoft Azure

以下来自 learn.microsoft.com 的全球文档，通读的是中文页。由世纪互联运营的 Azure 没有打开，不把下面的默认开关和保留天数套到那套环境。

### 软删除和版本控制默认都要自己开

[在 blob 软删除和 blob 版本控制之间进行选择](https://learn.microsoft.com/zh-cn/azure/storage/blobs/soft-delete-vs-versioning-options)（页上未见更新日期）写：这两项默认禁用，必须在存储帐户级启用。可以只用一个，也可以两个一起用。

- 软删除：保护平面命名空间帐户上的删除和覆盖；分层命名空间帐户只保护删除。保留期最多 365 天，可配置。覆盖会创建软删除快照，删除会创建软删除的 blob。用「设置 Blob 过期」API 过期的文件，不能靠软删除还原。
- 版本控制：保护平面命名空间上的删除和覆盖。先前版本一直留到被明确删除。每次写入创建一个新版本。不适用于已启用分层命名空间的帐户。
- 禁用软删除之后，新的删除是永久性的，但已经处于软删除状态的数据会留到各自的保留期结束。
- 软删除的内容不能用读取 API 直接读，要先取消删除。版本控制下的先前版本要用版本 ID 读取，不必先取消删除。

数据保护概述建议：为所有存储帐户启用容器软删除和 blob 软删除，最短保留间隔为七天。这是建议，不是对照页写的默认值。默认值仍是禁用。

### 版本控制可以关掉，但关不掉已有版本

[Blob 版本控制](https://learn.microsoft.com/zh-cn/azure/storage/blobs/versioning-overview)（页上未见更新日期）：启用后，创建以及之后每次修改都会生成带版本 ID 的新版本。版本 ID 是时间戳。先前版本的内容和元数据不能改。

不指定版本 ID 的删除：当前版本变成先前版本，不再有当前版本，已有的先前版本还在。指定版本 ID 才能删某一版。若同时还启用了 blob 软删除，该版本会保留到软删除保留期结束。

可以禁用版本控制。禁用不会删除现有 blob、版本或快照，只是之后不再创建新版本；再修改当前版本会得到一个不是版本的 blob，后续更新直接覆盖。已有版本仍可作为先前版本留着，仍可用版本 ID 读取或删除。帐户上还有对象复制策略时，必须先删掉这些策略才能禁用版本控制。同页故障排查还写：容器或帐户上若有不可变性策略，也可能无法禁用版本控制。

它不防止容器或帐户被删。删除容器会移除其中全部 blob 及其版本，要恢复得靠容器软删除。防止帐户被删，该页指向的是资源锁，不是版本控制。分层命名空间帐户，以及通过 Data Lake Storage API 上传的 blob，不支持版本控制。Put Block 不产生新版本。页 blob 的「放置页」、追加 blob 的「追加块」也不产生新版本，要留下这些写入，该页写的是手动快照。

和软删除同时开启时：覆盖会生成新的先前版本，这个新版本不会被软删除，一直留到被明确删除，软删除保留期不适用于这次「删掉的当前 blob」。删除某个先前版本时，该版本被软删除，保留到软删除期结束再永久删除。取消删除会还原该 blob 的全部已软删除版本，不能只还原其中一个，也不会把任何版本提升为当前版本。要回到某个先前版本，先全部取消删除，再用复制把那个版本复制成新的当前版本。

删除当前版本所需的数据操作，该页写成 `.../blobs/delete`，内置角色例子是存储 Blob 数据参与者。删除先前版本是 `.../blobs/deleteBlobVersion/action`，内置角色例子是存储 Blob 数据所有者。同一身份可以被授予两者。权限怎么收，见最小权限一文。

每个 blob 的版本很多时，列表会变慢。该页建议每个 blob 少于 1,000 个版本。生命周期若用 `daysAfterCreationGreaterThan`，时间从版本数据最初写入时算，不是从它变成旧版本的那次覆盖算。一个长期保持为当前版本的 blob，一旦被覆盖，旧版本可能马上超过这个天数而被删。计费按与活动数据相同的机制，对唯一块或页计；显式改层之后按该页的整对象规则计。单价不抄。禁用版本控制不会让已有版本停止计费，要自己删。

### 软删除保留 1 到 365 天，挡不住删容器和删帐户

[Blob 软删除](https://learn.microsoft.com/zh-cn/azure/storage/blobs/soft-delete-blob-overview)（页上未见更新日期）：启用时指定保留期 1 到 365 天。对象被删除或覆盖时开始算到期时间。保留期内用取消删除 Blob 恢复。可以随时更新配置的保留期限。禁用软删除后，仍可访问和恢复那些已经软删除、且保留期还没结束的对象。

已知限制里的另一句是：保留期限为 1 至 365 天，且不可延长；一旦保留期结束，不能再延长，对象被永久删除。前一句说配置可以随时改，后一句说已经结束的保留期不能再延长。两句都在这页，不并成「要么总能改、要么永远不能改」。

它只能恢复单个 blob，或分层命名空间里的目录，以及扁平命名空间下关联的快照和版本。不能靠它恢复容器。操作表写：删除存储帐户一行是「无更改」，已删除帐户中的容器和 blob 不可恢复。删除容器时，除非另开了容器软删除，否则容器里的 blob 无法恢复。容器软删除专页这次没有打开，不写它的保留天数范围。

[数据保护概述](https://learn.microsoft.com/zh-cn/azure/storage/blobs/data-protection-overview)（页上未见更新日期）另有一行：存储帐户若最初用 Azure 资源管理器部署模型创建，并且是在过去 14 天内删除的，删除后还没有用同名新建帐户，则可以尝试恢复已删除的存储帐户。这和软删除操作表「删帐户不可恢复」不是同一条路径。软删除表说的是软删除功能本身不改变删帐户的结果；概述说的是另一项帐户恢复条件。不要写成「开了软删除就能恢复帐户」，也不要写成「14 天一定能恢复」而不带该页的两个条件。

平面命名空间、未开版本控制时，覆盖（放置 Blob、放置块列表、复制 Blob）会自动生成写入前状态的软删除快照。更新元数据或属性不会生成这种快照，这些改动不能靠软删除找回。分层命名空间上，软删除只防止删除，覆盖不会留下可恢复的软删除快照。通过「设置 Blob 到期」删掉的 blob 不会变成软删除。放置页覆盖掉的页 blob 数据不会被保存。该页写 Azure 虚拟机用放置页写非托管磁盘，因此用软删除撤销虚拟机对非托管磁盘的写入，不是受支持的场景。非托管磁盘不是这篇的云盘快照，云盘快照见快照一文。

生命周期策略删除 blob、快照或版本时，软删除仍然适用，对象进入软删除而不是马上消失，保留期内继续按与活动数据相同的费率计费。若帐户启用了永久删除，有权限的调用者可以在保留期结束前永久删除软删除的快照和版本。要让整个保留期都有效，该页写的是禁用永久删除。

门户里看软删除 blob：容器视图中显示活动项和已删除项。编程列表用 `include=deleted`。只想列出活动 blob 时，不要用会把已删除项也算进去的 All 标志。

### 不可变性：到期后往往是能删、不能覆盖

[不可变存储](https://learn.microsoft.com/zh-cn/azure/storage/blobs/immutable-storage-overview)（页上未见更新日期）有两类策略，可以同时设。

- 基于时间的保留：间隔内可以创建和读取，不能修改或删除。间隔过后，对象可以被删除，但不能被覆盖。
- 法定保留：解除之前一直是 WORM。期间可以创建和读取，不能修改或删除。没有固定到期时间。

范围分容器级和版本级。容器级不要求先开版本控制，策略作用于容器内全部 blob，不能给单个 blob 另设一套。版本级必须以版本控制为前提，可以配在帐户、容器或版本上。帐户和容器层只能设基于时间的保留；blob 版本上可以同时有基于时间的保留和法定保留。多层都有时，优先顺序是 Blob、然后容器、然后存储帐户。若容器上已有法定保留，不能再给同一容器建版本级 WORM，因为法定保留会挡住生成这些版本。

保留间隔最小 1 天，最大 146,000 天（该页写 400 年）。有效保留期按 blob 创建时间与间隔计算。该页例子：策略为五年，已存在一年的 blob 还剩四年；新上传的 blob 从创建起算五年。策略间隔延长后，用最新的间隔重算。

第一次配置基于时间的策略时是解锁的，用于测试。解锁状态下已经不能删除和覆盖，但可以缩短、延长或删除策略。锁定后不能删除策略，可以延长、不能缩短。容器级已锁定策略在整个生命周期内，最多把有效保留期延长五次。针对 blob 版本的策略，延长次数没有这个上限。该页建议锁定时间通常不到 24 小时，不要把解锁状态留作长期方式。版本级策略的变更不会写入该页说的策略审核日志。

删除边界，两处都留着：

- 不可变存储页的对照表：容器级在锁定基于时间的策略后，只有容器是空的才能删除容器。版本级在帐户或容器层启用后，只有它们是空的才能删除。
- 数据保护概述的表：至少有一个容器启用了版本级不可变存储时，删除存储帐户会失败。容器里只要还有至少一个 blob，无论策略锁定与否，删除容器都会失败。容器上有法定保留或已锁定的基于时间的策略时，存储帐户也受保护而不能删除。没有设不可变性策略的容器，不受这条防删除保护。

分层命名空间支持容器级 WORM，不支持版本级 WORM。不可变存储与时间点还原、上次访问跟踪不兼容。启用了 NFS 3.0 或 SFTP 的帐户不支持不可变性策略。所有访问层和该页提到的冗余配置都支持。该页不建议给存放活动虚拟机 VHD 的页 blob 配不可变性策略。

软删除与不可变性一起用时：建议先开软删除再配策略。已经软删除的 blob，仍会在软删除保留到期后永久删除。还没被软删除的 blob 或版本受不可变性保护，要等基于时间的保留到期或法定保留解除之后，才能被软删除。

不可变存储本身不另收一笔容量费，计价方式与可变数据相同。版本级 WORM 因为开了版本控制，额外版本会带来版本控制那一页所说的容量。未付账单且已有基于时间的保留策略时，该页写按你与 Microsoft 的合同适用正常的数据保留策略，不在这里补删除时间表。

## Google Cloud

以下来自 docs.cloud.google.com。软删除的默认天数以今天打开的软删除页为准。

### 版本控制不保护删桶，指定 generation 才是永久删除

[Object Versioning](https://docs.cloud.google.com/storage/docs/object-versioning)（页上未见更新日期）建议：要防止意外或恶意删除造成的永久丢失，用软删除，而不是只用 Object Versioning。该页警告：只有软删除开启时，才能从已删除的桶里恢复对象。Object Versioning 不保护删桶。

在桶上开启后，替换或删除实时版本时，只要不指定这个实时版本的 generation，旧的实时版本会变成非当前版本，名称不变，用 generation 区分。非当前版本只在明确要求列出它们的请求里出现。关闭版本控制后，不再累积新的非当前版本，已经存在的版本不受影响。更改版本控制配置后，删除或替换可能在短时间内仍按旧设置执行。该页要求至少等 30 秒，再认为新设置已经生效。

非当前版本没有默认个数上限。每一版按它仍为实时版本时的同一费率计存储。提前删除费在版本从桶中移除时才计，不是在它变成非当前版本时就计；时长从加入桶的时间算，不是从变成非当前的时间算。存储类型和最短时长见生命周期一文。

参考表把软删除和版本控制的四种组合分开，不要记成「开了版本控制，删除就一定先进软删除」：

- 两者都关：删除 `dog.png`，或替换它，旧的实时版本永久删除。按 generation 删除非当前版本，也是永久删除。
- 只开软删除：删除或替换实时对象，旧对象进入软删除。按 generation 删除非当前版本，也进入软删除。
- 只开版本控制：不指定 generation 删除实时版本，它变成非当前版本，generation 不变。指定 generation 删除实时版本或非当前版本，永久删除。替换时，旧的实时版本变成非当前版本。
- 两者都开：不指定 generation 的删除或替换，仍是变成非当前版本，不是立刻软删除。指定 generation 删除实时版本或非当前版本，进入软删除。

非当前版本可以读。软删除对象不能读。把非当前版本恢复成实时版本时，若桶里已经有同名实时版本，旧的实时版本会再变成一份非当前版本，桶里会同时留下多份并继续计存储费。该页建议删掉用来做副本的那份非当前版本，或用生命周期在满足条件时去掉非当前对象。生命周期的具体天数和存储类型转换见生命周期一文。

### 软删除默认 7 天，也保住被删的桶

[Soft delete](https://docs.cloud.google.com/storage/docs/soft-delete)（页上未见更新日期）：对支持该功能的桶默认启用，默认保留 7 天。可以用标签改新桶的默认保留。保留时长可在 7 天到 90 天之间改；设为 0 即禁用。新建桶会自动带上默认软删除策略，例外是与软删除不兼容的产品，该页举的是使用 Rapid Bucket 的地带级桶。

修改保留时长只影响新策略生效之后才删除的资源。之前删的，仍按删除当时的时长保留。策略传播最多 30 秒。该页例子：先按 7 天删了 `object-A.png`，再把策略改成 10 天并删除 `object-B.png`，则 A 留 7 天、B 留 10 天。

软删除的对象和桶不能读、不能改、不能覆盖，只能列出或恢复。默认列表看不到它们。控制台恢复桶时，可以同时恢复桶和里面的对象。用 gcloud 或 JSON API 恢复桶，恢复的是空桶，对象要再单独恢复。桶名若已被一个新的实时桶占用，要先去掉这个冲突的实时桶，才能恢复软删除的同名桶。

项目被删除时：开了软删除的桶，保留时间取软删除保留时长和 Google Cloud 项目恢复窗口里较短的那个，之后永久删除。该页没有写出项目恢复窗口是多少天，不补。没开软删除的桶，可能在项目删除时立刻被删，并且可能无法恢复。恢复项目时，删除当时仍是实时的桶会作为实时桶恢复；当时已经软删除的桶继续软删除，直到它们自己的保留结束。

[恢复软删除对象](https://docs.cloud.google.com/storage/docs/use-soft-deleted-objects)（页上未见更新日期）：不能在一个仍处于软删除状态的桶里直接恢复对象，要先恢复桶。控制台在桶的对象页把 Show 选成 Soft-deleted objects only，再对版本点 Restore。命令行是 `gcloud storage restore`，对象后面带 `#` 和 generation；不写 generation 时恢复最新一版。批量恢复是异步的，有时要一个小时或更久才开始。列出和恢复所需权限，该页写可以向管理员要 Storage Admin（`roles/storage.admin`）。具体包括 `storage.objects.list`、`storage.objects.restore`、`storage.objects.create`；若恢复会覆盖现有对象，还需要 `storage.objects.delete`。谁应当拥有这些权限，见最小权限一文。

恢复会生成一份新的实时副本，原来的软删除版本仍留到保留期结束。若同名实时对象还在，恢复会覆盖它，被覆盖的那份再进入软删除。不论原来的存储类型或 Autoclass，恢复出来的对象写入 Standard。需要更多时间时，可以暂停该桶的硬删除；暂停期间，软删除对象无限期保留，并且继续计存储费，直到你恢复硬删除且原来的保留期结束。

和其他功能的关系，以软删除页为准：Object Lifecycle Management 不影响已经软删除的对象，不能用它改这些对象的存储类型，也不能用它把它们永久删除。被生命周期删除的对象会变成软删除。若同时开了版本控制，被删除的实时对象变成非当前版本，被删除的非当前对象变成软删除。XML API 分段上传的分片不受软删除保护。Autoclass 不对软删除对象收管理费，也不改变它们的存储类型。主要存放临时对象的桶，该页警告启用软删除可能显著增加存储费。

### 保留策略、锁定、对象保留锁和 hold 是四层

[Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock)（页上未见更新日期）：给桶加保留策略后，对象年龄大于保留期才能被删除或替换。策略追溯作用于桶里已有对象，也作用于之后新增的对象。年龄不够时，删除或替换失败，错误是 `403 - retentionPolicyNotMet`。该页例子：保留期 1 年，一个月前放入的对象还要再等 11 个月；两年前放入的对象可以马上删。替换一个已经到期的对象后，新版本的年龄从 0 重新算。

未锁定时，可以延长、缩短或去掉策略。锁定之后不能去掉，也不能缩短，只能延长。锁定不可逆。桶上还有未满足保留期的对象时，不能删除这个桶。想去掉已锁定的策略，该页写的办法是等到每个对象都满足保留期，然后删除桶。锁定还会给所在项目加上留置权，挡住 `resourcemanager.projects.delete`。要删项目，项目所有者或组织管理员得先去掉留置权。该页要求保持 Google Cloud 账号有效且状态良好；停用账号之前，要把数据转到另一个合要求的服务。停用之后数据会怎样，这页没有写成一张天数表，不补。

对象的可编辑元数据不受桶保留策略约束，对象本身不能删的时候，元数据仍可改。开了版本控制时，保留到期日还在未来的实时版本，仍可以被变成非当前版本；策略生效时桶里已有的版本化对象也受策略保护。生命周期可以自动删，但要等对象满足保留策略之后才会删。保留期最长 3,155,760,000 秒，该页换算为 100 年。控制台和 gcloud 用天、周、月、年时，该页的换算是 1 天 86,400 秒，1 周 7 天，1 个月 31 天，1 年 365.25 天。

[Object Retention Lock](https://docs.cloud.google.com/storage/docs/object-lock)（页上未见更新日期）是单个对象的保留配置，和桶级策略不同。retain-until 之前不能删除或替换，但对象仍可以变成非当前版本。最远可以设到距当前时刻 3,155,760,000 秒（100 年）。模式有两种：Unlocked，在 XML API 里叫 `GOVERNANCE`，授权用户可以修改或去掉配置；Locked，在 XML API 里叫 `COMPLIANCE`，日期不能缩短或去掉，模式一旦 Locked 不能再改，保留期只能加长。

只能在已经启用该功能的桶里给对象设置。已有桶只能用 Google Cloud 控制台启用这个功能。一旦启用，不能在桶上关闭。启用后会尽力给项目的 `projects.delete` 加上留置权；留置权还在时不能删项目。桶里还有未到期对象时，要等全部对象的 retain-until 已过，并且对象都已删除，才能删桶。对象可以同时受自己的保留配置和桶保留策略约束，两份都满足才能删。带事件型 hold 的对象不能再设保留配置。临时 hold 可以和保留配置同时存在。生命周期同样要等保留到期才会删。元数据可以改。

[Object holds](https://docs.cloud.google.com/storage/docs/object-holds)（页上未见更新日期）：hold 是打在单个对象上的标记。有 hold 时不能删除或替换，但可以改元数据。分事件型（event-based）和临时型（temporary）。对象没有自己的保留配置、所在桶也没有保留策略时，两种 hold 行为相同。桶有保留策略时：释放事件型 hold 会把该对象在桶中的计时重新开始，保留期再算一遍；释放临时 hold 不影响它已经累计的保留时间。该页的例子是 1 年保留期已经过完，两个对象都还有 hold，所以都还不能删；释放之后，事件型的那个要再留 1 年，临时型的可以马上删。

桶可以打开「默认事件型 hold」，之后新加入的对象自动带上事件型 hold，存量对象不会因为你后来打开这个默认值就被补上。分层命名空间的桶不支持 object holds。XML API 不能管理 hold，读取元数据时也不返回 hold 状态，但对象上有 hold 时，用 XML API 删除或替换仍会失败。

软删除页把 Bucket Lock 和 Object Retention Lock 写成：这两项会阻止你在保留政策满足之前删除对象；软删除再额外留一段软删除保留时间。因此保留期没到时，对象进不了软删除；保留期过了并被删除之后，若软删除仍开着，删除不会直接变成永久删除。

## 检查清单

按这个顺序做。每一步先确认账号在中国站、国际站，还是全球文档对应的环境。腾讯云国际站的回收站和对象锁定页、AWS 中国区文档和世纪互联运营的 Azure 这次没有打开。

1. 误删已经发生时，先别继续清空或指定版本删除。列出历史版本、删除标记或软删除对象。阿里云在文件列表里显示历史版本。腾讯云中国站看文件列表的历史版本，或回收站列表。AWS 在对象的 Versions 里看删除标记。Azure 在容器视图里显示已删除 blob，或按版本 ID 读先前版本。Google Cloud 把 Show 选成 Soft-deleted objects only；非当前版本要在列出版本的请求里才看得到。软删除对象在 Azure 和 Google Cloud 已打开的页面里不能直接当普通文件读取。
2. 确认当时桶的状态，而不是只看现在。阿里云、腾讯云、AWS 的版本控制一旦开启就不能回到未开启。暂停之后，新的 null 版本或删除标记可能覆盖旧的 null 版本，腾讯云暂停页写这种替换会丢掉 null 版本原来的内容。Google Cloud 改版本控制后至少等 30 秒再生效。Azure 可以禁用版本控制，但已有版本还在计费。
3. 恢复时优先做「复制成新的当前版本」，而不是永久删除当前版本。阿里云对象操作页、腾讯云实践页和 AWS 删除标记的恢复说明都提供了这条路。阿里云中国站不能把删除标记当作要恢复的那个历史版本。AWS 若要让旧版本重新变成当前版本，删的是删除标记本身的版本 ID；不带版本 ID 再删一次，只会再插入一个删除标记。
4. 要永久删除之前，先看保留策略和锁。阿里云锁定的桶级策略返回 `409 FileImmutable`，保护期内不能删桶。对象级策略是邀测，开了就不能关。腾讯云对象一旦锁定只能延长。AWS 合规模式在到期前连根用户也不能删该版本，不带版本 ID 的删除却仍会成功插入删除标记。Azure 基于时间的保留到期后可以删除，但不能覆盖。Google Cloud 未锁定的桶策略可以缩短或去掉；锁定后只能延长，并且项目上会有留置权。
5. 再用生命周期清理历史版本、删除标记和软删除对象。阿里云和 AWS：当前版本过期是加标记，非当前版本过期是永久删除。腾讯云中国站回收站的定期清理会写成一条生命周期规则，关掉开关会删掉这条规则。Azure 开着软删除时，生命周期删除进入软删除，永久删除功能可以提前清掉。Google Cloud 开着软删除时，生命周期删不掉已经软删除的对象。天数、存储类型和提前删除费见 [对象存储存储类型与生命周期](object-storage-storage-class-lifecycle.md)。
6. 核对谁能执行上面几步。阿里云配置版本控制要 `PutBucketVersioning`。腾讯云暂停版本控制和永久删除指定版本，概述限制为主账号或授权账号。AWS 只有根账号能开 MFA Delete；治理模式的绕过权限是 `s3:BypassGovernanceRetention`。Azure 删先前版本和删当前版本用的不是同一个数据操作。Google Cloud 恢复软删除对象，该页把 Storage Admin 列为包含所需权限的预定义角色。授权范围见 [云账号登录和权限怎么收紧](cloud-account-mfa-least-privilege.md)。
7. 删桶、删容器或删帐户之前再看一次保护范围。阿里云版本控制概述写当前没有回收站；保护期内有对象就不能删桶，但欠费停服仍可能删数据。腾讯云中国站回收站保住的是进入回收站的文件版本，删整个桶这次没读到。AWS 这次打开的 Recycle Bin 不包含 S3 对象。Azure 版本控制和 blob 软删除都不保护删容器、删帐户；容器要另开容器软删除，帐户恢复看概述里的 14 天和同名帐户两个条件。Google Cloud 只有软删除开启时，删桶才进入可恢复状态；版本控制本身不保护删桶。
8. 第二天再看容量。历史版本和软删除对象还在，账单里的存储费就不会因为「文件列表里已经看不到」而停。腾讯云中国站写删除标记不计存储容量费，历史版本计。Google Cloud 若暂停了硬删除，软删除对象会一直计费。存储类型单价不要用这篇的天数去推。

## 常见坑

- 把各云的「删除」都当成同一种可恢复操作。阿里云未开启版本控制时，概述表写删除后无法再获取。腾讯云不指定版本 ID 才是删除标记，指定版本 ID 是永久删除。AWS 简单 DELETE 留下标记，带版本 ID 的删除不能撤销。Azure 在软删除和版本控制都禁用时，删除是永久性的。Google Cloud 在两者都关闭时，替换会永久删掉旧的实时版本。
- 阿里云用暂停去「关掉」保护，并以为历史版本会一起消失。暂停后历史版本还在。null 版本在暂停期间可能被新的上传或删除标记覆盖。版本控制概述和保留策略页对「暂停的桶能不能开保留策略」说法相反，以你站点当前页和实际报错为准。
- 把腾讯云概述里的「回收站」比喻，当成已经开了回收站功能。概述说的是删除标记。回收站是另一页，要自己开启，而且会同步开启版本控制。国际站 112126 这次是 404。清空历史版本会彻底删除。
- 腾讯云对象锁定和桶的默认保留天数弄反。对象一旦锁定不能解除、不能缩短。桶的默认天数可以缩短、延长或关闭，而且只影响之后的新对象。开启桶的锁定开关，不会自动锁住存量对象。多 AZ 桶暂不支持。
- 把 AWS Recycle Bin 当成 S3 回收站。这次打开的页面支持的是 EBS 卷、快照和 EBS-backed AMI。S3 这边，不带版本 ID 的删除在 Object Lock 保护下仍会插入删除标记并返回 200，对象在列表里像消失了，版本还在。合规模式要在到期前删除该版本，该页写的是删除 AWS 账号，不是在控制台找一个关闭按钮。
- AWS 开了 MFA Delete 仍用控制台永久删版本。该页写这种删除不能走控制台，而且 MFA Delete 不能和生命周期配置一起用。生命周期的非当前版本过期仍会永久移除对象。
- Azure 只开了 blob 软删除，就认为容器和帐户也有同一张安全网。软删除操作表写删容器、删帐户不会因此变成可恢复。版本控制同样不保护删容器。分层命名空间上，软删除不保护覆盖，版本控制不适用。基于时间的保留到期之后可以删除，但不能覆盖，和「到期就恢复成普通对象」不是一回事。
- Azure 把「可以随时改保留期配置」和「保留期结束就不能延长」当成矛盾而忽略后一句。配置可以改；已经结束的那一次保留，该页写不能再延长，对象会被永久删除。永久删除功能还会在到期前清掉软删除的快照和版本。
- Google Cloud 只开版本控制，就认为删桶还能找回。版本控制页写只有软删除能从已删除的桶恢复对象。两者同时开启时，不指定 generation 的删除是把实时版本变成非当前版本，不是软删除；指定 generation 才进入软删除。
- Google Cloud 锁定桶保留策略或启用对象保留锁之后还想删项目。锁定桶策略会挡住项目删除，要先去掉留置权。对象保留锁启用后不能在桶上关闭。事件型 hold 释放后，桶保留期的计时会重新开始；临时 hold 不会。
- 用云盘快照去找对象存储里被删的文件，或用对象版本去回滚云盘。两边不是同一项资源。云盘见 [云盘快照与自定义镜像](disk-snapshot-custom-image.md)。
